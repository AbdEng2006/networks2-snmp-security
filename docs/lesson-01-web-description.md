# الدرس الأول: من فحص SNMP إلى صفحة ويب

## الهدف والنتيجة

عرض وصف الجهاز الحقيقي `sysDescr.0` في صفحة عربية مع زر لتكرار القراءة. هذه بداية صفحة System وليست إنجازًا لكل متطلبات الجزء الأول؛ لا توجد حقول تعديل بعد.

## التشغيل

افتح Terminal في جذر المشروع وشغّل:

```powershell
.\scripts\php.bat -d display_errors=0 -S 127.0.0.1:8080 -t public
```

اترك النافذة مفتوحة وافتح `http://127.0.0.1:8080` في المتصفح. لإيقاف السيرفر اضغط `Ctrl+C` داخل نافذته. هذا سيرفر تطوير محلي، ولا يحتاج Apache أو قاعدة بيانات.

- `scripts/php.bat`: يشغّل PHP بالإعداد المحلي الصحيح.
- `-d display_errors=0`: يمنع ظهور تفاصيل أخطاء PHP الداخلية في الصفحة.
- `-S 127.0.0.1:8080`: يستمع على هذا الجهاز فقط باستخدام المنفذ 8080.
- `-t public`: يجعل public جذر الملفات التي يستطيع المتصفح طلبها؛ config خارجه.

إذا كان المنفذ مستخدمًا من سيرفر المشروع الحالي، افتح الرابط مباشرةً. لتشغيل نسخة أخرى اختر منفذًا مختلفًا مثل 8081.

## الملفات وأسبابها

| الملف | وظيفته |
| --- | --- |
| `scripts/check-snmp.php` | فحص مستقل من Terminal لتشخيص الاتصال |
| `config/local.php` | إعداد اتصال هذا الجهاز؛ مستثنى من Git ولا نعرض محتواه |
| `config/example.php` | يوضح شكل الإعداد بدون أسرار حقيقية |
| `public/index.php` | ينفّذ القراءة ثم يولّد صفحة HTML |
| `public/assets/style.css` | تنسيق الصفحة والاستجابة لأحجام الشاشات |
| `public/assets/app.js` | مؤشر انتظار وتنسيق الوقت حسب جهاز المستخدم |

## مسار الطلب

1. المتصفح يرسل طلب HTTP للصفحة.
2. السيرفر ينفّذ PHP الموجود في بداية index.php.
3. PHP يحمّل إعداد الاتصال ويتحقق من القيم اللازمة.
4. PHP يستدعي snmp2_get باستخدام SNMP v2c والـOID الرقمي `1.3.6.1.2.1.1.1.0`.
5. Agent يعيد الوصف، أو يفشل الطلب بعد مهلة الانتظار والإعادات.
6. PHP يولّد HTML يحتوي النتيجة أو رسالة خطأ مفهومة.
7. المتصفح يعرض HTML ويحمّل CSS وJavaScript.

HTTP بين المتصفح وPHP مختلف عن SNMP بين PHP والـAgent. المتصفح لا يتصل بخدمة SNMP مباشرةً.

## قراءة إضافات PHP

- المتغيّر يبدأ بـ `$` مثل `$description`، ونستخدم `=` لإسناد قيمة إليه.
- بدأنا `$description` و`$error` بقيمة `null`، أي لا توجد نتيجة أو رسالة بعد.
- `header('Cache-Control: no-store')` يطلب عدم تخزين الصفحة مؤقتًا، حتى لا نعتمد على قراءة قديمة.
- فحص مسار HTTP يسمح فقط بالصفحة الرئيسية وindex.php، ويرجع 404 للروابط غير الموجودة بدل عرض الصفحة الرئيسية عليها.
- `microtime(true)` يقيس الوقت، والفرق بين البداية والنهاية يعطينا زمن المحاولة. الرقم يشمل إعداد الطلب، وليس اختبار ping أو زمن الشبكة وحده.
- `try` يحتوي التعليمات التي قد تفشل؛ `throw` يعلن الفشل؛ `catch` يلتقطه حتى نستطيع إظهار رسالة بدل توقف الصفحة الخام.
- `require` يحمّل الإعداد المحلي. لا نضع Community داخل HTML أو JavaScript.
- `@snmp2_get(...)` يكتم تحذير المكتبة؛ ما زلنا نفحص `=== false` لمعرفة الفشل. العلامة @ لا تعالج المشكلة.
- دالة `escape()` تستخدم `htmlspecialchars()` لتحويل محارف مثل `<` إلى نص آمن للعرض. بيانات Agent ليست كود HTML موثوقًا.
- `<?= ... ?>` اختصار لطباعة قيمة PHP داخل HTML.
- `if ... else` في القالب يختار عرض الاستجابة أو بطاقة الخطأ.

الرسائل المقصودة واضحة، أما الأخطاء الداخلية غير المتوقعة فلا نطبع تفاصيلها حتى لا تنكشف الإعدادات أو المسارات.

## HTML وCSS وJavaScript

HTML يصف المحتوى: عنوان رئيسي، قسم نتيجة، تفاصيل OID والوقت، ونموذج تحديث. `lang="ar"` و`dir="rtl"` يحددان اللغة والاتجاه؛ الاستجابة والـOID لهما اتجاه LTR للحفاظ على قراءة النص التقني.

CSS يضيف ألوانًا هادئة وتباينًا، وبطاقة استجابة، وحدودًا ومسافات. قواعد `@media` تعيد ترتيب البيانات على الهاتف. حالات النجاح والفشل لها نصوص ظاهرة، فلا نعتمد على اللون وحده. أضفنا مؤشر تركيز لاستخدام لوحة المفاتيح.

زر التحديث داخل `form method="get"`. عند الضغط يعاد طلب الصفحة بالكامل، وبالتالي يعاد تنفيذ PHP وإرسال SNMP GET. ليست هذه نسخة AJAX؛ اخترنا أبسط دورة طلب يمكن تتبعها في البداية.

JavaScript يضيف فقط تحسينين:

1. يعرض وقت آخر محاولة حسب المنطقة الزمنية للمتصفح؛ القيمة الأصلية في HTML محفوظة بصيغة UTC.
2. يغيّر نص الزر ويمنع ضغطه مرة أخرى أثناء إرسال النموذج، ويعلن الانتظار عبر `role="status"`.

القراءة والتحديث يعملان حتى بدون JavaScript، لكن بدون تنسيق الوقت المحلي ومؤشر الانتظار.

## التحقق وحدوده

- فحص بناء PHP بدون أخطاء.
- قراءة حقيقية ناجحة عبر HTTP وعرض استجابة الجهاز.
- الضغط على زر التحديث أعاد القراءة وغيّر وقت المحاولة.
- فحص التخطيط بعرض هاتف 390 بكسل بدون تجاوز أفقي.
- فحص غياب Community من HTML.
- طلب `/config/local.php` يرجع HTTP 404؛ ملف الإعداد خارج جذر الويب.
- تجربة تشغيل القالب بدون إضافة SNMP للتحقق من معالجة الخطأ.

لم نختبر تعديل أي قيمة؛ لا يوجد SET في هذه المرحلة. ولم نبنِ صفحة TCP أو سكربتات التشفير بعد.
